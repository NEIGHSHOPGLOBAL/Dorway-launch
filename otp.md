## 1. What you asked for, and what Meta allows

**You wanted:**

> OTP FOR LOGGING IN TO YOUR DORWAY ACCOUNT IS {otp}, expires in 5 min

**You cannot send that.** Meta fixes the body text on authentication templates. From their documentation: (cite index="21-1">authentication templates consist of fixed, non-customizable preset text — `<VERIFICATION_CODE> is your verification code` — an optional security disclaimer, an optional expiration warning, and either a one-tap autofill button, a copy code button, or no button if using zero-tap</cite>. (cite index="24-1">No headers are allowed, the body text is generated by Meta, and only the OTP code can be passed as a variable</cite>.

Writing your own OTP copy is not a matter of getting it past review. The Template Manager will not accept the text at all.

**What you actually control:**

| Element | Control |
|---|---|
| Body wording | None — Meta's fixed string |
| Security line | On/off toggle, Meta's wording |
| Expiry line | On/off + the number of minutes (1–90) |
| Button type | `COPY_CODE`, `ONE_TAP`, or `ZERO_TAP` |
| Button label | Up to 25 characters |
| Template name | Yours |
| Language | Yours |
| Header, footer text, URLs, media, emoji | Not allowed |

### Could you use a UTILITY template instead and write your own copy?

Technically the editor will let you. **Don't.** Meta is explicit that if you offer verification codes over WhatsApp you must use an authentication template, so an OTP sent as a utility template is a policy violation. The consequences land on the WABA that your entire paid CRM depends on: template rejection, template pause, or quality-rating damage that throttles your messaging tier.

There is also a practical loss. The copy-code button is the best part of WhatsApp OTP — one tap, no transcription errors, measurably better completion. A utility template with your own wording has no such button. You'd be trading a policy violation for a worse user experience.

## 2. Prerequisites — check these before you submit

Meta gates authentication templates: (cite index="28-1">your Meta Business Portfolio must be verified, and your WABA's messaging limit must be Tier 1 (2,000) or above</cite>.

| Requirement | Where to check | Status |
|---|---|---|
| Business verification complete | Business Manager → Security Centre | `[VERIFY]` |
| Messaging limit ≥ 2,000/24h | WhatsApp Manager → Phone numbers → Limits | `[VERIFY]` |
| Phone number registered and connected | WhatsApp Manager | `[VERIFY]` |
| Display name approved | WhatsApp Manager | `[VERIFY]` |

**A new WABA starts at 250 unique recipients per 24 hours**, which is under the gate. Tiers step up with sustained volume at a good quality rating. If you're at 250, this template cannot be created today and no workaround changes that — ship email OTP (`architecture_launch.md` §5) and come back when the tier lifts.

## 3. The template

### 3.1 Submission values

| Field | Value |
|---|---|
| **Name** | `dorway_login_otp` |
| **Category** | Authentication |
| **Language** | English — `en` |
| **Security recommendation** | ✅ On |
| **Code expiration** | ✅ On, **5** minutes |
| **Button type** | Copy code |
| **Button label** | `Copy code` |
| **Message send TTL** | 60 seconds |

Template names must be lowercase with underscores only. No spaces, no capitals, no hyphens.

**On button choice — pick `COPY_CODE`.** One-tap autofill is Android-only and requires your app's package name and signature hash, which you don't have because you're shipping a web app. Zero-tap needs the same plus accepting additional terms. Copy code works everywhere, on every device, with no app dependency. Revisit when the React Native port lands (`dorway.txt` §7.9).

**On the 60-second TTL.** If the message can't be delivered within 60 seconds it's dropped rather than arriving late. For a code that dies at 5 minutes, a message landing at minute four is worse than no message — the user has already asked for another one. `[VERIFY]` the minimum permitted TTL for authentication templates in your account.

### 3.2 What the user actually sees

```
┌─────────────────────────────────────────┐
│  Dorway                                 │
│                                         │
│  482915 is your verification code.      │
│  For your security, do not share        │
│  this code.                             │
│                                         │
│  This code expires in 5 minutes.        │
│                                         │
│  ─────────────────────────────────────  │
│           ⧉  Copy code                  │
└─────────────────────────────────────────┘
```

The code renders bold — the underlying body string is `*{{1}}* is your verification code.`

It doesn't say "Dorway account" anywhere in the body. Your **display name** at the top of the chat is what identifies you, which is why getting that approved correctly matters more than the template copy you can't change.

## 4. How to submit

### Option A — Template Manager (recommended)

1. WhatsApp Manager → **Account tools** → **Message templates** → **Create template**
2. Category: **Authentication**
3. Name: `dorway_login_otp` · Language: **English**
4. Tick **Add security recommendation**
5. Tick **Add expiry time for the code**, set to **5** minutes
6. Button: **Copy code**, label `Copy code`
7. Submit

The editor shows a live preview. There is no body text field to fill in — if you're looking for one, that's the restriction in §1, not a bug.

### Option B — API

```bash
curl -X POST \
  'https://graph.facebook.com/v23.0/<WABA_ID>/message_templates' \
  -H "Authorization: Bearer $WA_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "dorway_login_otp",
    "language": "en",
    "category": "AUTHENTICATION",
    "message_send_ttl_seconds": 60,
    "components": [
      {
        "type": "BODY",
        "add_security_recommendation": true
      },
      {
        "type": "FOOTER",
        "code_expiration_minutes": 5
      },
      {
        "type": "BUTTONS",
        "buttons": [
          {
            "type": "OTP",
            "otp_type": "COPY_CODE",
            "text": "Copy code"
          }
        ]
      }
    ]
  }'
```

Note there is no `text` property on the BODY component. That is correct and intentional — Meta supplies it.

### Multi-language

To submit several languages at once, use `upsert_message_templates` with a `languages` array instead of a single `language` string. `[VERIFY]` the current endpoint shape before relying on it.

`[CONFIRM — W7]` Is Hindi worth adding? Your buyer is an Indian SMB owner, and a Hindi OTP reads as more trustworthy to a chunk of that audience. Meta localises the fixed body itself, so it costs you one extra submission and no copywriting. The client picks the language you specify in the send call, so you'd need a language preference on the user record. Suggest shipping `en` first and adding `hi` in October.

## 5. Approval

Authentication templates are usually approved fast — often minutes — because (cite index="22-1">they consist only of preset text and buttons, which significantly minimises their risk of being paused</cite>. There is nothing in the content for a reviewer to object to.

`[VERIFY]` — do not promise anyone a timeline. Meta's review times vary and you have no control over them.

**If it's rejected**, the cause is almost never the template:

| Reason | Fix |
|---|---|
| Not eligible for authentication category | §2 prerequisites — usually the 2,000 messaging tier |
| Business not verified | Complete verification first |
| Name already exists | Names are unique per WABA; increment or delete the old one |
| Invalid name format | Lowercase and underscores only |

Rejection reason appears in Template Manager. Fix and resubmit — there's no penalty for a resubmission.

## 6. Sending

The code goes into **both** the body component and the button component:

```json
{
  "messaging_product": "whatsapp",
  "recipient_type": "individual",
  "to": "919876543210",
  "type": "template",
  "template": {
    "name": "dorway_login_otp",
    "language": { "code": "en" },
    "components": [
      {
        "type": "body",
        "parameters": [{ "type": "text", "text": "482915" }]
      },
      {
        "type": "button",
        "sub_type": "url",
        "index": "0",
        "parameters": [{ "type": "text", "text": "482915" }]
      }
    ]
  }
}
```

**The `sub_type` is `url`, not `otp`.** You create the button as `otp` but send it as `url` — (cite index="25-1">in the creation request the button type is designated as `otp`, but upon creation the button type is set to `url`</cite>. Getting this wrong is the most common first-integration failure, and the error message doesn't make the cause obvious.

Omitting the button parameter also fails. Both, every time.

Full integration detail, error mapping and fallback logic: `whatsapp.md` §4.

## 7. Cost

Authentication templates are billed per conversation, at rates that vary by country. India has historically had its own authentication rate.

`[VERIFY]` current Indian authentication pricing in Meta's pricing documentation before you model this. Two things to factor in:

- **Every login costs money.** Including failed attempts, including users who request three codes because the first didn't arrive. Budget on attempts, not on successful logins.
- **`dorway.txt` §2 flags a pricing change on 1 October 2026** — one week after your launch. Verify whether it touches authentication-category conversations. If it does, your per-login cost changes a week in.

This is the strongest practical argument for keeping email as the primary channel and WhatsApp as the upgrade: email OTP costs effectively nothing, and it can't be rate-limited by Meta.
